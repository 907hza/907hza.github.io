CS는 "왜 이 파이프라인이 느리고, 왜 죽는가"를 설명하는 도구입니다. 데이터 엔지니어 관점에서 우선순위를 매기면 아래와 같습니다.

| 과목 | 꼭 알아야 할 것 | 실무 연결 지점 |
|---|---|---|
| 자료구조·알고리즘 | 해시, 트리(B-Tree), 힙, 정렬·합병, 시간/공간 복잡도 | 인덱스 구조, Spark 셔플·조인 전략, 코딩테스트 |
| 운영체제 | 프로세스/스레드, 메모리(가상메모리·페이징), 파일시스템, I/O, 동시성·락 | OOM 분석, 디스크/네트워크 병목, 병렬 처리 설계 |
| 네트워크 | TCP/IP, HTTP/REST, DNS, TLS, 로드밸런서 | API 수집, 클러스터 통신 장애, 보안 구간 |
| 데이터베이스 | 트랜잭션·ACID, 격리 수준, 인덱스, 실행 계획, 정규화 | 쿼리 튜닝, CDC·정합성, Iceberg ACID 이해 |
| 분산 시스템 | CAP, 복제·파티셔닝, 합의, exactly-once / at-least-once, 멱등성 | Kafka 전달 보장, 재처리 설계, 장애 복구 |
| 컴퓨터 구조 (가볍게) | 메모리 계층, 캐시, 직렬화, 컬럼나 포맷 | Parquet/ORC가 빠른 이유, 압축·인코딩 |

## 추천 자료

- 『데이터 중심 애플리케이션 설계(DDIA)』: DB·분산시스템·스트리밍을 한 번에 엮어 주는 핵심 도서입니다.
- 코딩테스트는 기초 자료구조 수준이면 충분한 경우가 많습니다.
