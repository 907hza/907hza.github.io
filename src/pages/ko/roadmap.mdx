Python·SQL·Airflow·Spark를 기본기로 다지고, Kafka/CDC 실시간 처리, Kubernetes, Iceberg 기반 레이크하우스, dbt, AI 데이터 파이프라인까지 단계적으로 확장합니다. "써봤다"보다 <strong>"운영해봤다"</strong>고 말할 수 있도록 장애 대응, 재처리 전략, 데이터 유실 방지, 비용 최적화, 기술 선택의 트레이드오프를 함께 정리합니다.

## 학습 일정 (약 12개월)

평일 주 20시간을 기준으로 하면 전체 로드맵은 약 12개월입니다. Python·SQL·Airflow는 이미 실무에서 쓰고 있으므로 1–3단계는 점검 수준으로 줄였습니다.

시간은 두 트랙으로 나눕니다.

- **출퇴근 (하루 2시간, 주 10시간) = 입력**: 책·강의·공식 문서·기술 블로그. 휴대폰으로 볼 수 있는 것만 둡니다.
- **퇴근 후 (하루 2시간) = 실습**: 주 4일만 계획하고 1일은 밀린 것을 따라잡는 버퍼로 둡니다. 실습은 모두 포트폴리오 프로젝트에 축적합니다.

## 포트폴리오 프로젝트

하나씩 단계를 쌓아 가는 방식입니다.

1. **배치 ELT**: 공공/금융 API → Airflow → S3(Parquet) → dbt 마트 → BI 대시보드. 멱등성·backfill·품질 테스트 포함.
2. **실시간 CDC**: PostgreSQL → Debezium → Kafka → Spark/Flink → Iceberg, Trino로 조회. 지연·정합성 측정 결과 정리.
3. **플랫폼화**: 위 파이프라인을 Docker/Helm으로 K8s에 배포, Terraform·GitHub Actions·Grafana 모니터링 추가.
4. **AI 확장**: 문서 데이터를 청킹·임베딩해 벡터 DB에 적재하는 RAG 데이터 파이프라인.

현재 실무에서 하고 있는 일도 "문제 → 선택한 기술과 이유 → 수치로 본 결과" 형식으로 함께 정리합니다.
